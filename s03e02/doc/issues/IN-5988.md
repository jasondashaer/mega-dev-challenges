## Intent
Add a column to the CSV export with the booking's channel: link, widget or API (the Channel primitive
in specs/product.md).

## Acceptance
- Given bookings made through the link, the widget and the API, when the CSV is exported, then the new column reads link, widget and API for them.
- Given any export, when it is compared with one made before the change, then every existing column is there with the same values in the same relative order, and not one is lost (PRD-3).
- Given the new column, when it is added, then it goes after the existing columns and does not shift any of them.

## Boundaries
- Must not remove, rename or move existing columns (PRD-3); clients parse them (IN-3153).
- Must not change date formats (IN-3303 waits on a person).

Allowed by AUT-1 (new columns, filters or fields that add to what is there and take nothing away).

## Request
can the CSV export get a column for where the booking came from — link, widget or API?
