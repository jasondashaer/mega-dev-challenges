## Intent
The CSV export quotes fields as RFC 4180 says, so a comma, quote or line break inside a value no
longer shifts the columns.

## Acceptance
- Given a client named "Smith, Jones & Co", when the CSV is exported, then the name stays in its own column and every later column is in place.
- Given a value with a double quote, when exported, then the quote is doubled inside a quoted field.
- Given an export with no commas in any value, when compared with one made before the change, then it has the same columns in the same order, and not one column is lost (PRD-3).

## Boundaries
- Must not add, remove or reorder columns (PRD-3).
- Must not change time formats (SCHED-4446 adds the offset column separately).

Allowed by AUT-1 (bug fixes and small features inside the specs, with a test that shows the change).

## Request
the CSV export breaks when a client name has a comma in it. the columns shift by one from there.
